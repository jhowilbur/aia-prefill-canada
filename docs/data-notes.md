## Free text describing the system (the model's input)
Three different kinds of text exist; they are NOT equivalent for the test:
1. **Free-text answers inside the AIA** (comment/text fields, admin fields like respondent excluded): present in 32 of 32 JSON AIAs; length min 379 / median 8,375 / max 44,928 chars; >= 2,000 chars in 28, >= 5,000 in 24. The project description field alone (projectDetailsDescription) is filled in 32 of 32 (min 60 / median 1,290 / max 8,916 chars). **Leakage warning:** these were written by the same team in the same form, often justifying the selected option (for example impact8 explains impact7). Using them as input measures "read the AIA's own narrative", not "read system documentation".
2. **Independent text** = open.canada.ca dataset description + supporting documents that are not the AIA (GBA+ summaries, peer-review summaries, model descriptions): dataset description in 39 of 39; supporting documents in 14 of 39. Combined length min 155 / median 1,830 / max 144,098 chars; >= 2,000 chars in 18 of 39, >= 10,000 in 13; among the 32 JSON AIAs: >= 2,000 chars in 15, >= 10,000 in 10. These raw figures are NOT the model input: they include the f77faef4 AIA-annex DOCX (143,602 chars, AIA text) and peer-review files, whose mere presence reveals level II (audit round 2, M-A). The leakage-free input and its counts are in `docs/inputs.md`.
3. **The AIA rendered as PDF**: contains the questions AND the answers; never use it as input. Kept only for score/level (`aia_pdf_text_files`).

`description_text` in each interim file is 1 + 2 concatenated (as specified); the split fields `free_text_answers`, `ckan_notes`, `supporting_text` keep the parts apart. **None of them is leakage-free as is:** `supporting_text` contains AIA annexes and peer-review files. The only model input is `data/interim/inputs` (built by `pipeline/build_inputs.py`, rule and counts in `docs/inputs.md`).

## Limits
- Small sample: 32 AIAs with question-level labels (+7 PDF-only). Impact levels 3 and 4 are absent: no ground truth for high-impact systems.
- Survey drift: the exports span several tool versions; some ids were renamed or dropped, so per-question labels for older AIAs are partial against the current questionnaire, and old answer weights may differ.
- Selection bias: only systems departments chose to publish (mostly IRCC/ESDC triage tools).
- No real system documentation (design docs, model cards) is published; the independent text is short summaries.
- PDF text comes from `pdftotext -layout`; tables can lose order. DOCX text is raw XML text.
- Score/level are read from the AIA PDF; when a dataset has several assessment versions the PDF may not match the chosen JSON.
