Numbers from `python3 -I pipeline/g0_check.py --history` → `reports/g0_score_check.csv`
(one row per AIA with a tool JSON export; 32 AIAs; the 7 PDF-only AIAs have no parsed answers).
Truth = published raw score / level read from the AIA PDF. Answers = the export's `data`.

## What changed

1. **Full tool history** cloned (no checkout, no build) into `data/interim/aia-history/repo`
   (canada-ca/aia-eia-js, 1,068 commits, HEAD b625733 = vendored commit). The `version` written
   into each export is `state.version` in `store.ts`, bumped at c33b74d (v0.9, 2021-03-11),
   8cc9b5f (v0.9.1, 2021-11-30), aca5ce7 (v0.10.0, 2023-01-28), 4489fa9 (v1.0.0, 2024-12-04),
   b900dc7 (v1.0.1, 2025-10-03).
2. **Scoring code never changed** across these versions (hasScore, getValue, max, calculateFinalScore,
   `getAllQuestions().filter(hasScore)`); only `survey-enfr.json` did. So a version = its survey.
   Canonical survey of a version = last survey revision before the next bump, exported by
   `pipeline/aia_versions.py export` to `catalog/versions/<version>/survey-enfr.json` with
   `catalog/versions/manifest.json` (max raw: v0.9/v0.9.1 107, v0.10.0 126, v1.0.x 167).
3. `aia_score.score(survey, data, version=None)`: default unchanged; `version="v0.9.1"` etc.
   scores with that survey. `aia_score.convert_loaded_file` reproduces the two conversions the tool
   applies when an old file is re-opened (ActionButtonBar.vue: aboutSystem1 `item6-1`→`item6`
   from v0.9.1; `impact4`→`decisionSector3` from v0.10.0).
4. **Which version scored the published number**: the score PDF prints `Version: x.y.z`. The
   check uses that version when it is known, else the export's `version`. They differ for
   2 AIAs: aafdfbcd (JSON v0.9.1, PDF 0.10.0: the file was re-opened in v0.10.0 before printing;
   v0.9.1 gives 56/level III, v0.10.0 gives the published 55/level II) and cea9985f (PDF "0.8",
   no such survey snapshot exported; JSON v0.9.1 used, matches).

## Remaining mismatch (1)

- **6b429c8e** (ESDC EI ML workload, v0.10.0): published 30 / level I, recomputed 35 / level II.
  The 5 points come from `businessDrivers5` (+1), `businessDrivers11` (+2) and `impact30` (+2).
  The PDF's own answer table disagrees with the JSON: Q4 "How effective will the system likely be"
  shows *Very effective [Points: +0]* while the JSON holds `item2-1` (+1). So the published PDF and
  the published JSON are from **different edits** of the assessment. The history search
  (`history_revisions_matching_raw` column) finds 30 only with survey revisions 4709d24–c11e208
  (2023-03-11 → 03-28, pre-release v0.10.0, where those questions had other names), but the JSON
  uses the post-87c6bc5 names, so a pre-release build alone does not explain it. Keep the
  published level as truth; flag this AIA in any per-question analysis.

## Caveats
- Version-to-survey mapping uses the last revision of each version; for v0.10.0 the survey changed
  23 times under the same string (all in March–April 2023). All 19 matching v0.10.0 AIAs match the
  final revision, none needed an interim one.
- v1.0.0 is ambiguous (the 2025 rewrite was done under that string); no published AIA uses it.
- `data-notes.md` said "11 of 32, 0 of 10 for the oldest versions": that was the current survey
  applied to all versions. The cause was survey drift, confirmed.
